# Evidence: retiring the em dash

Project: [issue #20](https://github.com/hyperscaleailabs/core/issues/20).
Collected 2026-07-30 on the project branch.

**Evidence tier: process.** Nothing here is a claim about a physical or
simulated system. It is proof that the tree is clean, that the guard catches the
rule in every direction that matters, and that a 660-replacement rewrite of
published prose did not change what a reader sees beyond the punctuation.

## Baseline

| Measure | Before | After |
|---------|-------:|------:|
| Em dashes, whole tree | 766 | 64 |
| Em dashes, in scope | 667 | 0 |
| Em dashes, excluded frozen artifacts | 64 | 64 |
| Em dashes in `atlas/public/search-index.json` | 35 | 0 (regenerated) |
| Files rewritten | - | 104 |
| Em dashes rendered across the built site | 766 source | **0 across 49 pages** |
| Atlas build | 50 pages, 37 indexed, 0 diagnostics | unchanged |
| prod unit / e2e | 57 / 4 | 57 / 4 |

The 64 remaining are the two frozen artifacts, excluded on purpose and
documented in the guard rather than in a comment nobody reads:

- `prod/app/agent_simulation_control_plane_mvp.html` (10) - the shipped v0.1.0
  MVP. `'—'` there is a **table value meaning "not applicable"**, rendered to an
  operator. Replacing it would edit the product, not the punctuation.
- `prod/docs/v0.1.0/` (54) - the archived handoff package documenting a released
  ZIP. Its text is supposed to match what shipped.

`atlas/public/search-index.json` was going to be excluded as generated output
and, in the end, was **not**. It carries frontmatter only - title, description,
section, level, tags, url, flags - never article bodies, so it went clean the
moment those fields did and stays clean even though several articles now quote
the character in code blocks. Leaving it in scope means an em dash appearing
there is a real signal: either a title or description carries one, or the
committed index has drifted from the corpus.

## 2. Two hazards a global replace would have caused

**A line-leading em dash becomes a list item.** Three occurrences were wrapped
sentence continuations:

```markdown
This is the mechanism behind the entire [agent loop](/foundations/what-is-an-agent)
— the atlas covers its design tradeoffs in depth under [tool use](/patterns/tool-use).
```

Replacing the `—` in place yields `- the atlas covers...`, which Markdown renders
as a **bullet**. The transformer refused to touch line-leading dashes and
reported them; all three were reflowed by hand. Rendered result, read back off
the running site:

| Page | Rendered |
|------|----------|
| `foundations/building-with-the-claude-api` | "the mechanism behind the entire agent loop - the atlas covers its design tradeoffs in depth under tool use." |
| `learning-paths/architect-track` | one list item: "Tradeoffs & failure modes by architecture - the complexity ladder and what each rung costs." |
| `news/2026-06-agent-ecosystem-roundup` | "traversing it for connected context - see the pattern writeup for when the build cost is worth it." |

No stray bullets; each is a single continuous sentence.

**An em dash used as data, not punctuation.** `atlas/docs/content-guide.md`
documented `license: "—"` as the marker for an unknown source license. The
transformer turned it into `license: " - "`, which is not a value. Checked
whether any article actually used it (none do) and replaced the documented
placeholder with `"unknown"`.

## 3. One cosmetic artifact, found and fixed

`atlas/src/pages/index.astro` held `>— {v}<`. The fallback rule produced
`> -  {v}` - a double space. HTML collapses it, so nothing looked wrong on the
page, but the source was sloppy. Found by diffing added lines for
`\S {2,}- |\S - {2,}\S`, which returned exactly one hit across the whole change,
and fixed to `- {v}`. Rendered list after the fix:

```text
01  sources.yaml - curated reference links + versions
02  diff - skip anything already processed
03  fetch + extract - pull and clean new/changed pages
04  plan + draft - outline -> 5-15 min Markdown article
05  index + PR - rebuild index, open a review PR
```

## 4. The guard fires in every direction

`tools/policy/check_writing.py`, exercised with decoys in seven directions:

| # | Case | Expected | Exit | Result |
|--:|------|----------|-----:|--------|
| 1 | Prose em dash in a **new untracked** file | fail | 1 | `sdlc/_decoy.md:1: A sentence — here.` |
| 2 | Em dash inside an `inline code` span | pass | 0 | quoted, not punctuation |
| 3 | Em dash inside a fenced code block | pass | 0 | quoted, not punctuation |
| 4 | Prose em dash **after** a closed fence | fail | 1 | `sdlc/_decoy.md:4: Now prose — with a dash.` |
| 5 | Em dash in a `.py` comment | fail | 1 | `sdlc/_decoy.py:1: # a comment — with a dash` |
| 6 | Em dash in an excluded frozen path | pass | 0 | exclusion holds |
| 7 | Em dash in a `.gitignore`d file | pass | 0 | not scanned, correctly |

Case 4 also confirms line numbers survive fence masking: the fenced block is
blanked in place rather than removed, so the violation is reported at line 4,
where it actually is.

Two things the first version got wrong, both caught by running it:

- **Scope was `git ls-files`**, so a brand-new document was invisible until it
  was staged and the author would have got the failure from CI instead of the
  terminal. Changed to `git ls-files -co --exclude-standard`, matching
  `check_links.sh`, which closed the same gap for link checking in the previous
  project.
- **It could not let the repository document its own rule.** The first version
  was a shell script grepping whole files, and it failed on this project's own
  article, lesson, evidence, and Lab Notes entry - eleven violations, every one
  of them the character being *quoted* inside `inline code` or a fenced block to
  show the hazard. A rule about prose has to know the difference between using a
  character and naming it. Rewritten in Python with fence and code-span
  awareness; cases 2, 3, and 4 are that distinction under test.

The stale-exclusion check exists because the two exclusions are load-bearing. An
exclusion pointing at a path that has moved is a rule nobody can see is dead.

## Not covered

- **103 en dashes in 36 files** are untouched. `AGENTS.md` forbids the em dash
  specifically, and most of these are numeric ranges (`5-15 min`), where the en
  dash is correct typography. Widening the rule is a writing-standard decision
  for the Architect, not a cleanup, and it is not guarded here.
- Curly quotes and apostrophes are likewise untouched and unguarded, for the
  same reason.
- `pre-commit run --all-files` did not run; `pre-commit` is not installed on this
  host. Its hooks were reproduced individually - see the PR's Evidence section.
